# AtFlows 0.1.1

AtFlows 0.1.1 adds opt-in AtMem-owned dashboard authentication. When configured,
one AtMem account, password and role controls both local dashboards. AtFlows
checks the live AtMem session on protected requests, so a disabled account or
changed role loses the corresponding AtFlows access. Standalone AtFlows login
remains the default and existing account files are retained.

## Install and upgrade

```bash
python -m pip install --upgrade atflows==0.1.1
atflows --version
```

Bun 1.1 or newer is needed to run the local server. Upgrading from 0.1.0 keeps
the AtFlows data directory and local users. No migration or automatic mode
switch occurs. For standalone operation, run `atflows init` as before.

To delegate dashboard login and user management, first start AtMem's dashboard,
then replace the placeholder with the URL printed by `atmem status`:

```bash
export ATFLOWS_ATMEM_AUTH_URL=http://127.0.0.1:ATMEM_PORT
atflows init
```

Keep the variable set for every `atflows start` or `atflows init`; delegated mode is read at server startup, not persisted by `init`. Open both dashboards with the same numeric host, `127.0.0.1`. Sign in at AtMem;
AtFlows will recognize the active account. The AtFlows Users page and local
credential recovery are disabled in delegated mode; manage users and passwords
in AtMem. AtFlows sign-out also ends the AtMem session. Existing standalone
AtFlows users are not imported or deleted. Restart without the setting to
restore their use.

The authority URL must be a same-host numeric-loopback HTTP origin. If AtMem is
unavailable or its session is revoked, protected AtFlows requests are denied.
This release does not change OTLP/proxy authentication, automatically send
AtMem traces, unify databases, or add AtFlows MCP/AtBot intelligence. The
AtMem review-lead handoff remains a separate explicit operation.
