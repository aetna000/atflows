# AtFlows 0.1.4b2 — Hermes observation and secret-safe telemetry

AtFlows 0.1.4b2 is a prerelease that adds a first-class Hermes connection path
and groups timeline events by service and run. It also applies the shared
redaction guard before events are persisted or shown in the dashboard.

## Install or upgrade

```bash
python -m pip install --pre --upgrade "atflows==0.1.4b2"
atflows --version
atflows
```

The dashboard and proxy URLs are printed at startup. The default listeners are
loopback-only. Bun 1.1+ is still required for the bundled dashboard runtime.

## Hermes setup

Open the dashboard's **Connect → Hermes** panel, review the loopback endpoint,
then apply it and restart Hermes. The equivalent preview check is:

```bash
atflows connect hermes preview --endpoint http://127.0.0.1:<dashboard-port>
```

The native Hermes observer emits bounded metadata (request/tool/error labels,
counts, timing, and token usage when supplied). It intentionally excludes
prompts, tool arguments, model responses, authorization headers, and API keys.

## Compatibility and limitations

- This beta is paired with AtMem 2.3.8b2 but remains usable independently.
- Existing OTLP, proxy, SQLite, and AtMem-delegated dashboard paths remain
  available.
- Hermes must be restarted after applying setup. A preview is not an active
  connection, and an installed plugin is not proof that Hermes has selected it.
- Telemetry is local-only by default and is not a hosted multi-tenant service.

No database migration is required for existing AtFlows data. If the beta is
rolled back, keep the existing data directory and reinstall the previous
published version.
