# AtFlows 0.1.5

Stable release of the Windows private-state protections introduced in 0.1.5b1.
Authentication records and integration backups are protected with verified
Windows ACLs before writes. POSIX state remains owner-only; existing traces,
accounts and configuration are preserved. Protection failures stop the affected
write. Invalid Codex TOML continues to be rejected across supported Bun versions.

## Install or upgrade

```sh
python -m pip install --upgrade atflows==0.1.5
atflows --version
```

Python 3.10+ and Bun 1.1+ are required for the service. Back up configuration
and the local database, stop the instance you own, upgrade and restart with
`atflows start`. Use `atflows init` only for initial setup. Installing a wheel
does not start telemetry collection. Clients must explicitly configure the
proxy or OTLP endpoint. Existing dashboard login and trace formats are retained.

AtMem-managed installations use the exact AtFlows pin selected by AtMem;
upgrade AtMem instead of overriding that dependency. AtMem 2.3.11 selects 0.1.5.
Standalone AtFlows retains its own accounts; delegated mode uses AtMem accounts.

## Compatibility and limits

The runtime behavior is unchanged from 0.1.5b1; this is a stable promotion.
Windows uses built-in Windows PowerShell for ACL protection, which can add
seconds at startup. Administrators and the OS remain trusted. Native Hermes
integration is unavailable on Windows; use a supported host or WSL.
Offline regression checks do not establish live model-provider availability.
AtFlows reports telemetry and known prices; it does not authorize memory or
prove a workflow succeeded. Website publication is a separate reviewed step.
