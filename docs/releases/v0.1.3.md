# AtFlows 0.1.3 — See how work resumes

AtFlows 0.1.3 adds continuity observability alongside AtMem 2.3.7, plus grouped
event charts and a consistent AtMem dashboard font system.

## Highlights

- **Follow resumed work:** Activity → Resume work connects workflow, operation,
  run and attempt identities. See retries, recovery attempts and reported costs.
  Unknown prices stay unknown; overlapping retry/recovery charges count once.
- **See patterns before individual events:** Timeline's new Group by chart
  shows tool, service, model, event type or hour. Click a bar to inspect events.
  It covers the latest 100 matching events, not all-history totals.
- **Consistent dashboards:** body text, headings, navigation and wordmark follow
  AtMem. SQLite startup now configures its busy timeout before continuity schema
  creation, allowing an existing writer time to finish.

## Install and upgrade

```sh
python -m pip install --upgrade "atflows==0.1.3"
atflows --version
atflows init
atflows start
```

Standalone AtFlows requires Bun 1.1 or newer. For the coordinated setup, use
`python -m pip install --upgrade "atmem==2.3.7"` then `atmem init` and
`atmem status`; AtMem manages startup and reports the actual local URLs.
Stop existing writers and back up the AtFlows SQLite database before upgrading.
Restart long-running servers after installation. The continuity tables are
additive; existing telemetry remains separate.

## Enable continuity observation

Follow [the integration guide](../integrations/continuity.md). Configure
`ATFLOWS_CONTINUITY_TOKEN` on the server and producer, restart the server, and
connect the producer SDK or AtMem observer. This is explicit instrumentation,
not automatic capture of every tool or model call. Investigator access or higher
is required for the continuity dashboard. AtFlows never authorizes execution;
AtMem owns saved state, permission decisions and receipts.

## Evidence and scope

The coordinated installed document workflow survived both a crash after a saved
receipt and a crash before receipt persistence, leaving one published document
in each case. In the public retail fault check, AtMem-connected configurations
avoided a repeated exchange request by stopping for confirmation. AtFlows records
the attempts; it is not a retry-prevention mechanism itself.

See the [AtMem continuity report](https://github.com/aetna000/atmem/blob/main/benchmarks/agent_continuity/reports/product-continuity-20260925.md)
for raw evidence and distinct test scopes. Repeated held-out evaluations remain
future work; these results are not a general task-success or cost-reduction claim.
