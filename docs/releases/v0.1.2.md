# AtFlows 0.1.2

AtFlows 0.1.2 makes the local observability dashboard easier to recognize and navigate alongside AtMem. The browser title and favicon use the AtMem.ai identity, and a link to the AtMem dashboard appears when AtFlows is using AtMem-delegated login. Server log timestamps use local time with an explicit offset.

## Install and upgrade

```bash
python -m pip install --upgrade atflows==0.1.2
atflows --version
```

Bun 1.1 or newer is required to run the server. The first launch may need network access to prepare the bundled runtime. Upgrading from 0.1.1 keeps the existing AtFlows data directory and accounts; there is no database migration or automatic login-mode switch. If you run AtFlows independently, use `atflows init` for first setup and `atflows start` after that.

When AtMem 2.3.5 starts AtFlows as a managed companion, `atmem init` and `atmem status` report the selected local ports and any startup problem. Existing standalone AtFlows users remain available when the delegated-login setting is absent. The AtMem link is shown only when delegated login is configured; standalone mode does not imply a connection to AtMem.

## Compatibility and limits

AtFlows 0.1.2 retains the optional AtMem-delegated dashboard authentication introduced in 0.1.1. The setting `ATFLOWS_ATMEM_AUTH_URL` still takes effect at server startup, not from `atflows init` persistence. AtMem 2.3.5 pins this AtFlows version; earlier AtMem 2.3.4 pins 0.1.1. The AtFlows dashboard remains a separate local service and database. This release does not authenticate the OTLP receiver or model proxy, automatically send traces to AtMem, or turn trace data into canonical memory. Keep listeners on a trusted interface.
