# AtFlows 0.1.4b3 — Native Hermes observability

AtFlows 0.1.4b3 is a prerelease for observing real Hermes agent activity in a
separate, filterable service bucket. It adds native Hermes event ingestion to
the guided setup and grouped timeline views introduced in the previous beta,
plus truthful connection status based on real traffic rather than configuration
alone.

## Install or upgrade

```bash
python -m pip install --pre --upgrade "atflows==0.1.4b3"
atflows --version
atflows
```

The dashboard and proxy remain loopback-only by default. Bun 1.1 or newer is
required by the bundled local runtime.

## Hermes setup

Use **Connect → Hermes** in the dashboard, or preview and apply from the CLI:

```bash
atflows connect hermes preview --endpoint http://127.0.0.1:1337
atflows connect hermes apply --preview PREVIEW_ID
```

Restart Hermes, run one normal turn, then check the connection. Hermes is shown
as connected only after AtFlows receives a real matching event.

## Compatibility and limitations

- Intended companion for AtMem 2.3.8b6; AtFlows also works independently.
- Existing OTLP, proxy, SQLite, grouped timeline, and AtMem-managed login paths
  remain available.
- The Hermes observer stores bounded telemetry and usage metadata. It excludes
  prompts, responses, tool arguments, authorization headers, and API secrets.
- That exclusion applies to the native Hermes observer. General proxy and OTLP
  telemetry redaction remains planned for the stable 0.1.4 security release.
- Cost remains unknown when the host does not report sufficient model usage.
- Hermes must be restarted after setup changes. Existing historical telemetry
  is not relabelled as Hermes traffic.

No database migration is required. To roll back, stop AtFlows, reinstall the
previous version, and keep the existing data directory.
