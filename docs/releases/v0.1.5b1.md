# AtFlows 0.1.5b1 — Windows private-state candidate

This prerelease improves protection of local dashboard authentication records
and Codex integration backups on Windows. It applies and checks a protected
Windows access-control list before writing the corresponding local state;
on macOS and Linux those paths remain owner-only. Existing local state is kept.
If the operating system cannot protect the path, the operation fails instead
of continuing with an unprotected write. Administrators and the operating
system remain trusted principals. It also accepts Bun's alternative error
diagnostic when rejecting an invalid Codex configuration.
Windows protection uses the built-in Windows PowerShell and can add a few
seconds to initial setup and startup. Live model-provider availability was not
established by the offline server checks.

Install in an isolated Python environment:

```sh
python -m pip install --upgrade --pre 'atflows==0.1.5b1'
atflows --version
```

AtFlows remains useful standalone. AtMem-managed deployments select the version
pinned by the AtMem release; upgrade AtMem rather than overriding that pin.
This is a candidate, not a new stable release. Existing traces and local
configuration should be backed up before upgrading. The optional native
Hermes integration remains unavailable on native Windows; use a supported
host or WSL for that integration.
